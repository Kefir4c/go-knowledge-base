🗺️ ЭТАЛОННЫЙ РОАДМАП: POSTGRESQL ДЛЯ GO-РАЗРАБОТЧИКА
🟢 РАЗДЕЛ 1. JUNIOR (Фундамент)
Цель: Научиться создавать структуры данных и писать базовые запросы.

1.1. Типы данных и их размерность
Логика: Прежде чем создать таблицу, нужно знать, из чего делать столбцы. Ошибка в типе данных = проблемы с производительностью или потеря точности (особенно с деньгами).
Что учить: BIGSERIAL, NUMERIC (для денег), TEXT vs VARCHAR, TIMESTAMPTZ (всегда с зоной!).
Связь с Go: BIGINT → int64, NUMERIC → string (чтобы не потерять точность), TIMESTAMPTZ → time.Time.

1.2. Создание таблицы и ограничения (Constraints)
Логика: Таблица есть, но нужно защитить её от мусора. Например, чтобы у пользователя был email, а баланс не стал отрицательным.
Что учить: CREATE TABLE, NOT NULL, UNIQUE, PRIMARY KEY, CHECK, DEFAULT.
Связь с Go: Как обрабатывать ошибки нарушения UNIQUE и CHECK в Go (например, pgx.Error).

1.3. Базовый CRUD (INSERT, SELECT)
Логика: Таблица создана, теперь научиться класть и доставать данные.
Что учить: INSERT INTO ... RETURNING, SELECT * FROM ....
Связь с Go: Функции CreateUser с возвратом ID, GetUserByID, обработка sql.ErrNoRows.

1.4. Базовая фильтрация (WHERE)
Логика: В таблице 1 млн строк. Тянуть все в Go — самоубийство. Нужен поиск по условиям.
Что учить: =, >, <, !=, IS NULL, IS NOT NULL.
Связь с Go: Динамическое построение WHERE-части запроса в Go (опциональные фильтры).

1.5. Продвинутый поиск (LIKE / ILIKE)
Логика: Нужно искать по части слова (например, имя начинается на "Алекс").
Что учить: LIKE, ILIKE (регистронезависимый), %, _.
Связь с Go: Функция поиска по имени. Запомни: LIKE без индекса — нагрузка на базу.

1.6. Сортировка и пагинация (ORDER BY, LIMIT, OFFSET)
Логика: Вывести 10 пользователей на страницу сайта.
Что учить: ORDER BY, LIMIT, OFFSET. Проблема большого OFFSET (почему становится медленно).
Связь с Go: REST-эндпоинт /users?page=2&limit=10.

1.7. Связи таблиц (FOREIGN KEY)
Логика: Хранить пользователя и 1000 его заказов в одной таблице — плохо. Нужно разделить и связать.
Что учить: Связь «Один-ко-многим», FOREIGN KEY, ON DELETE CASCADE vs RESTRICT.
Связь с Go: Структуры User и Order в Go. Раздельное хранение.

1.8. Объединение таблиц (JOIN)
Логика: Начальник хочет отчёт: «Выведи имя пользователя и сумму его заказа». Данные в двух таблицах, надо склеить.
Что учить: INNER JOIN (только совпадающие), LEFT JOIN (все из левой, даже без совпадений).
Связь с Go: Запрос, который возвращает пользователей с их заказами в виде структуры.

1.9. Агрегация (GROUP BY, HAVING)
Логика: Сколько заказов сделал пользователь? Какова общая сумма его покупок?
Что учить: COUNT(), SUM(), AVG(). GROUP BY. HAVING (фильтр после группировки).
Связь с Go: Запрос для Dashboard: топ-5 пользователей по сумме покупок.

🟡 РАЗДЕЛ 2. MIDDLE (Производительность)
Цель: Делать запросы быстрыми и защищать данные.

2.1. Порядок выполнения запроса (SQL Lifecycle)
Логика: Ты пишешь SELECT, но база выполняет его не так, как ты думаешь. Понимание порядка помогает оптимизировать.
Что учить: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.

2.2. Индексы: Ракета для запросов (B-Tree)
Логика: SELECT по email на 10 млн строк тормозит 2 секунды. Нужен быстрый поиск.
Что учить: B-Tree, CREATE INDEX. Составной индекс (порядок полей важен). Частичный индекс (WHERE active=true). Индекс по выражению (LOWER(email)).
Связь с Go: Медленный запрос в Go → ты создаёшь индекс и проверяешь.

2.3. Диагностика (EXPLAIN ANALYZE)
Логика: Ты создал индекс, но уверен ли, что база его использует?
Что учить: EXPLAIN ANALYZE. Разница между Seq Scan, Index Scan, Index Only Scan. Чтение cost, rows.
Связь с Go: Запусти EXPLAIN ANALYZE для запроса из Go в psql.

2.4. Продвинутые запросы (CTE, Окна)
Логика: Нужно показать заказ и рядом сумму предыдущего заказа этого же пользователя. Обычный GROUP BY не поможет.
Что учить: Подзапросы, WITH ... AS (CTE), ROW_NUMBER(), LAG(), LEAD(), PARTITION BY.
Связь с Go: Реализация отчёта с оконными функциями.

2.5. Транзакции и конкурентность (ACID)
Логика: Твой Go-сервис работает в 1000 горутин. Две одновременно списывают деньги с одного счёта. Это беда.
Что учить: BEGIN, COMMIT, ROLLBACK. Уровни изоляции. FOR UPDATE. SKIP LOCKED. Deadlock.
Связь с Go: Реализация перевода денег в транзакции. Обработка deadlock (повтор попытки в Go).

2.6. MVCC и VACUUM: Как база хранит данные
Логика: DELETE удалил строку, но место на диске не освободилось. Почему?
Что учить: Многоверсионность (xmin, xmax). Мёртвые строки (Bloat). VACUUM и AUTOVACUUM.
Связь с Go: Почему после удаления логов в Go база не худеет.

2.7. Профилирование запросов (pg_stat_statements)
Логика: Как найти тормозной запрос на живом сервере?
Что учить: log_min_duration_statement. Расширение pg_stat_statements.
Связь с Go: Настройка логирования медленных запросов.

🟠 РАЗДЕЛ 3. SENIOR (Архитектура)
Цель: Пережить высокие нагрузки и не потерять данные.

3.1. Партиционирование (Разделяй и властвуй)
Логика: Таблица логов выросла до 500 ГБ. Индексы не влезают в память.
Что учить: Декларативное партиционирование (RANGE по дате). Partition Pruning.
Связь с Go: Notification Service пишет логи. Партиции по месяцам.

3.2. JSONB и GIN-индексы
Логика: Настройки уведомлений для каждого пользователя разные. Делать 50 таблиц — бред.
Что учить: Тип JSONB. Операторы ->, ->>, @>. GIN-индекс.
Связь с Go: Хранение map[string]interface{} или структуры в JSONB. Быстрый поиск.

3.3. Пулы соединений (pgxpool)
Логика: 1000 горутин открывают 1000 соединений → Postgres умирает.
Что учить: pgxpool. Настройка размера пула. PgBouncer.
Связь с Go: Настройка пула в Go-сервисе, чтобы не убить базу.

3.4. Репликация и Высокая доступность (HA)
Логика: Сервер с Postgres упал. Как сделать так, чтобы база не была единой точкой отказа?
Что учить: Master-Slave репликация. Синхронная vs Асинхронная. WAL (Write-Ahead Log).
Связь с Go: Как Go-сервис должен вести себя при падении мастера.

3.5. Тюнинг конфигурации (postgresql.conf)
Логика: Сервер с 64 ГБ RAM, а база тормозит. Конфиг по умолчанию настроен на «домашний комп».
Что учить: shared_buffers, work_mem, maintenance_work_mem, effective_cache_size.
Связь с Go: Настройка сервера под нагрузку от Go-сервиса.
